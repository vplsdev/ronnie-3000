# + Menu Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** In the Archetype layout, the + button opens a black menu: categories with a lane choice, then library and
TONE3000 results for one category with a search, then load-from-file and the full tone browser, as on the approved
boards ArchAddMenu, ArchAddResults and ArchAddSignedOut.

**Architecture:** The menu is a small state machine in a new `archetype/add_menu.rs`, kept in egui temp memory like
`Focus`, drawn over the stage with an `egui::Area`. "Your library" is a new list of recently loaded tones
(`services/recent_tones.rs`), saved through the existing text preference so that it survives restarts and works signed
out. TONE3000 results come from a second `CatalogStore` owned by `ChromeController`, whose queries carry a scope so
that results reach the right store. Picking a tone sets the load target to the chosen lane's insert block and starts
the load **without** opening the browser; the added block then opens on the stage.

**Tech Stack:** Rust, egui/eframe, the `UiDriver` test harness (`crates/ui/tests/archetype_ui.rs`), `rfd` for the file
dialog.

**Spec:** docs/superpowers/specs/2026-11-11-archetype-ui-design.md ("+ at the end opening a black Archetype-style menu
(categories, then library and TONE3000 results, then load from a file)"); boards ArchAddMenu, ArchAddResults,
ArchAddSignedOut on https://claude.ai/artifact/CaaEinMfx2MVib3hPSNz7x (approved 2026-11-11).

## Global Constraints

- The reference layout must not change. Its + / tile flows and the browser stay as they are.
- Menu colours: fill #0b0b0b, hover row #1d1d1d, hairline #262626, text #f2f2f2, muted #8a8a87, search field #1a1a1a
  with border #2e2e2e, accent #ff6a1a. Corner radius 8, padding 8, width 380, anchored under the + button.
- The + button draws solid #111 with a white plus while the menu is open, dashed outline otherwise.
- Copy is fixed by the boards: "ADD BLOCK", "to", "LANE A", "LANE B", "to the end of the chain", "PEDAL", "AMP",
  "AMP + CAB", "CAB", "OUTBOARD", "SPACE", "LOAD A FILE…", ".nam · .wav", "OPEN THE TONE BROWSER",
  "filters, sort, pages", "YOUR LIBRARY", "TONE3000", "TRENDING", "ADD", "IN CHAIN", "DOWNLOADING",
  "SHOW ALL <n> <CATEGORY>S IN THE TONE BROWSER", "SIGN IN", "Sign in to search and download from the TONE3000 community
  library.".
- Category hints: Pedal "Overdrive, distortion, fuzz, boost, compressor"; Amp "Heads and combos, no cab"; Amp + Cab
  "A whole rig in one capture"; Cab "Impulse responses, mic positions"; Outboard "Preamps, rack EQ and compressors";
  Space "Rooms and reverbs".
- Category → TONE3000 gear value: Pedal "pedal", Amp "amp", FullRig "amp+cab", Cab "cab", Outboard "outboard",
  Space "space" (the values `filters.rs` already sends).
- New blocks go to the end of the chosen lane (its insert block), as + does today.
- `make check` green.

## Review Focus

- Picking a tone while another load is still downloading: the first load is dropped (LoadFlow's gate), the second
  lands, and no stale "DOWNLOADING" row stays.
- Switching to mono while the menu is open with LANE B chosen: the menu falls back to "to the end of the chain" and adds
  to lane A.
- A recent local tone whose stash file was collected: the load fails with the existing toast, and the tone stays in
  the library (no crash, no silent removal).
- A corrupt or oversized `archetype.recent_tones` preference: the library starts empty, and the next load rewrites it.
- Signing out while results are showing: the TONE3000 section turns into the sign-in box on the next frame.

### Task 1: Recent tones (the library)

**Files:** Create `crates/ui/src/services/recent_tones.rs` (+ `mod` line in `services/mod.rs`). Modify
`crates/ui/src/services/load_flow.rs`, `crates/ui/src/default/header.rs` (ChromeController). Test: unit tests in
`recent_tones.rs`, `crates/ui/tests/archetype_ui.rs`.

**Interfaces — Produces:**
- `pub struct RecentTones { tones: Vec<Tone> }` with `pub const KEY: &str = "archetype.recent_tones"`,
  `pub const MAX: usize = 24`, `pub fn from_text(text: &str) -> Self` (bad JSON → empty),
  `pub fn to_text(&self) -> String` (JSON array of each tone's `raw`), `pub fn remember(&mut self, tone: Tone)`
  (newest first; a catalog tone replaces the entry with the same `id`; a local tone replaces the entry with the same
  title and first model `stash_name`; keeps `MAX`), `pub fn tones(&self) -> &[Tone]`,
  `pub fn in_category(&self, category: GearCategory) -> Vec<&Tone>`, `pub fn count(&self, category: GearCategory) -> usize`.
  A tone's category is `identify(&GearHints::from_tone(tone, tone.models.first())).family.category()`.
- `LoadFlow::take_landed(&mut self) -> Option<Tone>`: the tone of the last successful `land` or `finish_remote`, once.
- `ChromeController::recent_tones(&self) -> &RecentTones`. The controller seeds it from
  `backend.text_preference(RecentTones::KEY)` in `new`, and after each `take_landed` (polled where `sync_browser` runs)
  remembers the tone and dispatches `UiAction::SetTextPreference { key: KEY, value: to_text() }`.
  `ChromeController::drop_file_into(insert_id: &str, path: &Path) -> Result<(), UiError>` dispatches `DropFile` and
  then remembers the tone that the target lane's new block holds.

- [ ] Tests (unit): `remember_puts_the_newest_first`, `a_catalog_tone_is_kept_once_by_id`,
  `a_local_tone_is_kept_once_by_file`, `the_list_keeps_twenty_four`, `bad_text_gives_an_empty_library`,
  `text_round_trips` (from_text(to_text) keeps ids and titles), `tones_sort_into_gear_categories` (a tone with
  `"gear": "amp"` counts under Amp, `"gear": "pedal"` under Pedal).
- [ ] Test (archetype_ui): `a_loaded_tone_joins_the_library` — main-mono, click "Add a block" then pick a tone with
  `pick_tone` as in `the_block_you_add_opens_on_the_stage` (Task 2 changes how the browser opens: until then use
  `chrome.gallery_mut().activate(insert)`); after settling, `chrome.recent_tones().tones()[0].title` is the tone's title
  and `backend.text_preference(KEY)` contains it.
